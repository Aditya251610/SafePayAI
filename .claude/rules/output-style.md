# Output style rule (HARD RULE)

- Short bullet points. Simple. Explainable. Not long prose paragraphs — the user reads bullets, not essays.
- Applies to every response, not just task-completion summaries — explanations, findings, answers to "what does X do", all of it.
- When explaining what code or a script does: walk through it as short, concrete bullets (what it creates, what it doesn't do, when it actually runs) — not a narrative paragraph.
- Keep responses practical and decision-oriented.
- Do not open with long preambles or task narration. Write concise, scannable updates.
